# Message Makeover — Interview Examples

Use these fictional drafts for a live demonstration. The outputs below are illustrative examples of suitable wording, not recorded AI responses. The live model may choose different wording; compare the facts rather than expecting an exact match.

## One draft, different formats

Paste this draft:

```text
Hi Alex, you still havent sent the project file. i need it by 3 PM today to finish the review. please let me know if you cant send it by then.
```

Say:

> “The message already contains the facts. I want to change how it sounds without changing Alex, the project file, the 3 PM deadline, or why I need it. I’ll show the same draft as a short chat message and a professional email.”

Keep **Intent: Follow up** and **Grammar-only: Off** for the first three runs. Change the preferences and click rewrite for each run; changing a preference clears the previous result.

### 1. Friendly, short chat

**Settings:** Friendly · Follow up · Short · Chat message

Illustrative result:

```text
Hi Alex, could you send the project file by 3 PM today? I need it to finish the review. Please let me know if you can’t send it by then.
```

Explain:

> “The wording is warmer and concise, but the deadline and request to flag a delay remain.”

### 2. Professional email

**Settings:** Professional · Follow up · Balanced · Email

Illustrative result:

```text
Subject: Project File Needed by 3 PM Today

Hi Alex,

I’m following up on the project file. Please send it by 3 PM today so I can finish the review.

Please let me know if you cannot send it by then.
```

Explain:

> “Email format adds a subject and readable paragraphs. It should not invent a sender name or add a promise.”

### 3. Firm, detailed chat

**Settings:** Firm · Follow up · Detailed · Chat message

Illustrative result:

```text
Hi Alex, I’m still waiting for the project file. Please send it by 3 PM today, as I need it to finish the review. If you cannot send it by then, please let me know.
```

Explain:

> “Firm means direct and respectful. It should not invent consequences. Detailed uses the information already present; it does not manufacture extra context just to make the message longer.”

### 4. Grammar-only correction

**Settings:** Grammar-only: On. Other rewrite controls are disabled.

Illustrative result:

```text
Hi Alex, you still haven’t sent the project file. I need it by 3 PM today to finish the review. Please let me know if you can’t send it by then.
```

Explain:

> “This mode fixes capitalization and punctuation while keeping the original wording. Turning it off restores my earlier preferences.”

## Two useful follow-up examples

### Preserve uncertainty

Draft:

```text
Hi Priya, i might finish the report by Wednesday, but i cant confirm that yet. i will share an update tomorrow.
```

**Settings:** Professional · Keep original · Balanced · Email · Grammar-only: Off

Illustrative result:

```text
Subject: Report Progress Update

Hi Priya,

I might finish the report by Wednesday, but I cannot confirm that yet. I will share an update tomorrow.
```

Explain:

> “A rewrite must not turn ‘might finish’ into a confirmed commitment. It must also keep tomorrow’s update and avoid using Priya, the recipient, as a sender signature.”

### Clarify a conflicting intent

Draft:

```text
I accept your invitation and will attend on Friday.
```

**Settings:** Professional · Decline · Balanced · Chat message · Grammar-only: Off

An appropriate clarification would be:

> “Do you want to accept the invitation as written, or decline it?”

Explain:

> “The chosen intent contradicts the draft. The app should ask me to clarify instead of silently reversing the meaning. I can update the draft and try again.”

## Finish the demonstration

Choose one successful result, edit a sentence, and copy it. Explain that copying uses the edited text, while the explanation describes the original AI rewrite. Show the journal or test report if asked about how the application was built and checked.

For a two-minute interview, use only the short chat and email runs, then edit and copy. Keep the remaining cases for follow-up questions. If the model fails, show the actual error and use the explicit retry; the illustrative outputs in this document are not a fallback inside the application.
